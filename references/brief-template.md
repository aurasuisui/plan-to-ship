# 派单模板(复制后填空)

```text
你在 <repo 绝对路径> 执行里程碑 <Mx>。<分支/HEAD>。

## 开工前必读
<计划文件路径>(只看 Mx 那一行与相关缺陷)、<仓库约定文件>。

## 范围
只改:<文件清单>
禁止:<文件清单(源码/测试/契约/版本文件)>

## 目标
<一句可验证的话>

## 验收(自己先跑,把原样输出留下)
1. <验证命令> → exit 0,输出贴原样
2. <测试命令> → 计数 = <基准>
3. <禁止出现的写法> → 0 命中

## 提交与汇报
- 在 <分支> 上提交,message 说清做了什么;**不要 push**(除非明确授权);
- 报「待审核」+ ①验证命令原样输出 ②测试计数 ③commit 列表 ④做法与偏离。
- **不要给自己判分**,不要改看板/台账;另附「发现但没动手改的问题」。

## 硬规矩
- 不引入依赖、不改公开接口语义、不削弱测试断言;
- 异常(命令失败、结果与预期不符)立刻停下报告,不要补救式重试。
```

## 派单时最容易漏的三句

1. **禁止清单**——不写,它就会"顺手"改测试或改契约。
2. **停下点**——不写,它失败后会自己发明方案。
3. **汇报格式**——不写,你收到的是一段自我评价,不是证据。

## 领域技能怎么带进派单

子智能体通常**能看到技能目录,但不会自动加载正文**(清单是它会话开始时的快照)。所以派单里必须点名 + 验证:

```text
## 开工前必读(顺序执行)
1. 调用 skill 工具加载 <domain-skill>;不要只凭技能名猜内容。
2. 加载后,用 3 行复述这次必须遵守的领域硬规则;复述不出就停下报告。
3. 计划:<plan.md>(只看 <Mx> 与相关缺陷)。
```

第 2 行是验证点:复述不出来 = 没真加载,直接打回。
兜底:若 `skill` 工具不可用或名字不在清单里,退回**直接读绝对路径** `<repo>/.agents/skills/<name>/SKILL.md` —— 路径对,内容就一定进上下文。

> 注意:会话开始后新增的技能,已运行的会话看不到;需要新开会话。
